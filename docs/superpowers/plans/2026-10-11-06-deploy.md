# План 6: деплой — Docker Compose + Caddy, бэкапы, версия протокола, реальный IP, E2E + хвосты 5b — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** готовый к запуску на одном VPS с доменом прод-стек:
- `compose.yml` с Postgres, игровым сервером, Caddy (HTTPS, статика клиента, прокси API и WebSocket) и ежедневными бэкапами;
- сервер видит реальный IP клиентов за прокси;
- открытые вкладки старой версии сами перезагружаются после деплоя;
- E2E на Playwright по спеке 9.6;
- пошаговая инструкция деплоя.

Плюс выбранные хвосты 5b: лимит по IP на `/chunk` и `/overview`, лимит отката по всему холсту, гонки доступа, полировка UI модерации.

**Architecture:**

```
                 Internet :80/:443
                        │
                 ┌──────▼──────┐  Caddy (image "web" = caddy + built dist)
                 │    caddy    │  - TLS (Let's Encrypt) for {$DOMAIN}
                 │             │  - /trpc/* /ws /chunk/* /overview /auth/* /health → server:3000
                 │             │  - everything else: /srv (dist), SPA fallback → /index.html
                 └──────┬──────┘    /assets/* immutable cache, index.html no-cache
                        │ compose network "internal" (no published ports below)
                 ┌──────▼──────┐  image "server" = bun + sources; NODE_ENV=production
                 │   server    │  TRUST_PROXY=1 → client IP from X-Forwarded-For (last hop)
                 └──────┬──────┘  migrations at boot, single writer (advisory lock)
                        │
                 ┌──────▼──────┐        ┌────────────┐
                 │  postgres   │◄───────┤   backup   │ pg_dump -Fc nightly 03:00 UTC,
                 │ (volume pg) │        │ (postgres) │ keep 14 → ./backups (bind mount)
                 └─────────────┘        └────────────┘
```

- **Один `Dockerfile`, две цели.**
  - `server`: `oven/bun:1.3.6`, `bun install --frozen-lockfile --production`, исходники, `bun apps/server/src/main.ts`. Сборки сервера нет, Bun выполняет TypeScript напрямую, как сейчас в dev.
  - `web`: стадия сборки `bun run build:web` → `caddy:2.10` с `dist` в `/srv` и `Caddyfile`.
- **Деплой:** `git pull && docker compose up -d --build` на сервере.
  - Простой — несколько секунд: graceful shutdown сохраняет состояние, клиенты переподключаются сами.
  - Если `PROTOCOL_VERSION` поменялся, вкладки перезагружаются один раз.
- **E2E-стек:** тот же образ, другой файл `compose.e2e.yml` на `http://localhost:8080`. В нём `DEV_LOGIN=1` и `NODE_ENV=development`, потому что в production dev-вход запрещён валидацией env. Свой compose-проект и свои тома, прод-данные не задеты. Playwright запускается скриптом `bun run e2e`.

**Tech Stack:** Bun 1.3.6, Docker Compose v2, Caddy 2.10, Postgres 17, Playwright (`@playwright/test`), bun test.

## Решения (согласованы)

| Вопрос | Решение |
|---|---|
| Куда | Один VPS с доменом; Caddy сам получает сертификаты Let's Encrypt. План создаёт только файлы и инструкцию, к серверам я не подключаюсь |
| Сборка | На сервере: `git pull` + `docker compose up -d --build`, без registry |
| Статика | Caddy отдаёт собранный `dist` (SPA fallback для `/admin`, долгий кеш хешированных ассетов) и проксирует API и WS на сервер |
| Бэкапы | Ежедневный `pg_dump -Fc`, хранятся 14; восстановление описано в инструкции |
| Версия протокола | `PROTOCOL_VERSION = 2`. При несовпадении клиент показывает «Игра обновилась — перезагружаем…» и перезагружается не чаще раза в 60 с (метка в `sessionStorage`); если чаще — просит обновить страницу вручную |
| Реальный IP | `TRUST_PROXY=1` → IP берётся из последнего элемента `X-Forwarded-For` (его добавляет Caddy). Порт сервера наружу не опубликован |
| E2E | Минимум из спеки локально: dev-вход, пиксель, вторая вкладка видит его; плюс `/admin` открывается и ассеты отдаются без 404 |
| Простой при деплое | Допустим (несколько секунд) |
| Секреты | `.env.production.example` с плейсхолдерами и пошаговая инструкция; реальные значения только на сервере |
| Доступ к БД | Только изнутри (`docker compose exec postgres psql` или SSH) |
| Хвосты 5b | Лимит по IP на `/chunk` и `/overview`; лимит отката по всему холсту; гонки доступа; полировка UI модерации |

Дополнительные решения, которые я принял сам (можно оспорить):
- **Лимит отката игрока по всему холсту — 200 000 клеток.** Иначе отказ `too_many_cells` с текстом «Слишком много клеток — откатите по областям или выберите меньший период». Значение — константа `MAX_ROLLBACK_CELLS` в `@rave/shared`.
- **Лимит по IP на `/chunk/*` и `/overview`:** отдельное ведро 120 запросов, 60/с. Обзор миникарты запрашивается раз в 5 с, чанки — несколько штук на экран, так что живым клиентам этого с запасом хватает.
- **Сервер запускается от непривилегированного пользователя `bun`** из базового образа.
- **Healthcheck'и.** Postgres — `pg_isready`. Сервер — `bun -e "fetch('http://localhost:3000/health')…"`. Caddy стартует после «здорового» сервера.
- **Логи** — стандартный драйвер Docker `json-file` с ротацией: `max-size 10m`, `max-file 5`.
- **E2E-проверка пикселя во второй вкладке** — через скриншот холста и цвет пикселя в центре. WebGL-холст нельзя прочитать из JS без `preserveDrawingBuffer`. Для разбора PNG нужна dev-зависимость `pngjs`.

### Task 1: Реальный IP клиента и лимит на `/chunk` / `/overview`

**Files:** Create `apps/server/src/net/client-ip.ts`, `client-ip.test.ts`; Modify `apps/server/src/net/env.ts`, `env.test.ts`, `server.ts`, `server.test.ts`, `deps.ts`, `.env.example`

- [ ] **Step 1: env.** Добавь `TRUST_PROXY: z.enum(["0","1"]).default("0")` и `ServerConfig.trustProxy: boolean`. Тест в `env.test.ts`. В `.env.example` добавь строку `TRUST_PROXY=0` с комментарием «1 только за доверенным прокси (Caddy в compose.yml)».

- [ ] **Step 2: `client-ip.ts`.**
  ```ts
  /**
   * Client address for rate limits. Behind our own proxy the TCP peer is the proxy, so the real address is the
   * last X-Forwarded-For entry — the one the proxy itself appended. Earlier entries come from the client and are ignored.
   */
  export function clientIp(req: Request, peer: string | undefined, trustProxy: boolean): string {
    if (trustProxy) {
      const last = req.headers.get("x-forwarded-for")?.split(",").at(-1)?.trim();
      if (last) return last;
    }
    return peer ?? "unknown";
  }
  ```
  Тесты:
  - без доверия заголовок игнорируется;
  - с доверием берётся последний элемент (`"1.1.1.1, 2.2.2.2"` → `"2.2.2.2"`);
  - пустой или отсутствующий заголовок → peer;
  - `peer` undefined → `"unknown"`.

  Если `Array.prototype.at` недоступен в целевом `lib`, используй индекс.

- [ ] **Step 3: `server.ts`.**
  - `route` вычисляет IP один раз: `clientIp(req, server.requestIP(req)?.address, deps.config.trustProxy)`. Его используют `/trpc` (`ipLimiter`) и `upgrade` (`hub.reserveConnection(ip)` и `socketData`).
  - Новое ведро `staticLimiter = deps.staticLimiter ?? new KeyedRateLimiter<string>(120, 60)` для `GET /chunk/*` и `/overview`; превышение → 429 `Too many requests`.
  - `AppDeps.staticLimiter?` — по аналогии с `ipLimiter`.
  - Тесты в `server.test.ts`:
    - с `trustProxy: true` два запроса к `/trpc` с разными `X-Forwarded-For` попадают в разные ведра: при `ipLimiter(1, 0)` оба проходят, а повтор с тем же IP получает 429;
    - без доверия — одно ведро;
    - `/overview` при `staticLimiter(1, 0)` — второй запрос получает 429.
  - Во всех тестовых `ServerConfig` добавь `trustProxy: false`.

- [ ] **Step 2: `version.ts` (чистая логика).**
  ```ts
  const KEY = "rb_reload_at";
  const MIN_INTERVAL_MS = 60_000;

  /** What to do when the server speaks another protocol: reload once, or ask the user if we just did. */
  export function onProtocolMismatch(storage: Pick<Storage, "getItem" | "setItem"> | null, now: number): "reload" | "ask" {
    const last = Number(storage?.getItem(KEY) ?? 0);
    if (now - last < MIN_INTERVAL_MS) return "ask";
    storage?.setItem(KEY, String(now));
    return "reload";
  }
  ```
  Доступ к `sessionStorage` оборачивай в `try/catch`; при ошибке передавай `null`, и тогда функция всегда возвращает `"reload"`. Цикла это не создаёт, потому что после перезагрузки бандл уже новый. Тесты:
  - первый вызов → `reload`;
  - второй через 30 с → `ask`;
  - через 61 с → `reload`;
  - `null` → `reload`.

### Task 3: Гонки доступа — одна очередь на пользователя

**Files:** Create `apps/server/src/admin/access-queue.ts`, `access-queue.test.ts`; Modify `apps/server/src/admin/service.ts`, `service.test.ts`, `apps/server/src/auth/ensure-player.ts`, `ensure-player.test.ts`, `apps/server/src/net/deps.ts`, `hub.ts`, `trpc/init.ts`, `main.ts`

- [ ] **Step 1: `AccessQueue`.**
  ```ts
  /** Serializes everything that reads and writes a user's access (ban, unban, first join), one chain per user. */
  export class AccessQueue {
    private chains = new Map<number, Promise<void>>();

    run<T>(userId: number, job: () => Promise<T>): Promise<T> {
      const previous = this.chains.get(userId) ?? Promise.resolve();
      const result = previous.then(job);
      const tail = result.then(() => {}, () => {});
      this.chains.set(userId, tail);
      void tail.then(() => {
        if (this.chains.get(userId) === tail) this.chains.delete(userId);
      });
      return result;
    }
  }
  ```
  Тесты:
  - задачи одного пользователя идут строго по очереди (вторая стартует после завершения первой);
  - разные пользователи идут параллельно;
  - ошибка не клинит очередь;
  - после завершения в карте не остаётся ключей.

- [ ] **Step 2: Перевод на очередь.**

  - Второй одновременный первый вход (`created: false`, пока перечитывание первого не закончено) ждёт очередь: `await accessQueue.run(user.id, async () => {})`.

- [ ] **Step 3: `deploy/backup.sh`.**
  ```sh
  #!/bin/sh
  # Nightly logical backup at 03:00 UTC; keeps KEEP_DAYS days of dumps.
  set -eu
  while true; do
    now=$(date -u +%s)
    next=$(date -u -d "$(date -u +%Y-%m-%d) 03:00" +%s 2>/dev/null || echo 0)
    [ "$next" -le "$now" ] && next=$((next + 86400))
    sleep $((next - now))
    file="/backups/rave-$(date -u +%Y%m%d-%H%M%S).dump"
    pg_dump -Fc -f "$file.tmp" && mv "$file.tmp" "$file" && echo "backup ok: $file"
    find /backups -name 'rave-*.dump' -mtime +"$((KEEP_DAYS - 1))" -delete
  done
  ```
