## Заметки для Плана 2 (из финального ревью Плана 1)

- **Снапшот игрока** сериализовать синхронно в момент `drainEvents()`, а не в async-коммите. Дедуплицировать `player`-события в батче. `charges` хранить вместе с `chargesUpdatedAt`.
- **`bannedUntil = Infinity`** не переживает JSON: маппить на Postgres `'infinity'` timestamp.
- **Создание игрока**: `createPlayer` не эмитит событий. Стартовые строки ledger (`start`), `player_state` и `inventory` пишет сервер (или перенести создание в движок).
- **Ledger**: строки `item='color'` нет (есть `color_unlocked` + coins с `ref.product='color'`). Либо синтезировать, либо убрать `color` из enum. Буст ёмкости — только coins-строка с `ref.product='chargeCapBoost'`.
- **Бомбы**: применять события батча последовательно (add → remove на одной клетке). Удаление — по `(season_id, x, y) WHERE removed_at IS NULL`.
- **Восстановление**: нужен `CanvasStore.loadChunk(cx, cy, colors, owners)` с пересчётом территории. `AntiFarm` засевать из `bombs` (`removed_reason='exploded'` за сегодня в TZ конфига). Загружать всех игроков сезона (владелец бомбы должен быть в реестре).
- **Лента**: `bomb_removed` содержит x, y — Broadcaster обязан вырезать координаты.
- **Принятое поведение**: при заморозке теряется частичный прогресс текущего заряда (до `regenMs − 1`). Решение Плана 1, не баг.

## Заметки для Плана 2b (из финального ревью Плана 2a)

- **Единственный писатель не защищён.** Два процесса на одной БД теряют пиксели (доказано пробой). На старте брать `pg_advisory_lock` на отдельном соединении до `loadGame`; все записи `pixel_events` (включая модерацию из Плана 5) — только через рантайм.
- **Связка `loadGame` → `GameRuntime` хрупкая**: забыть `dirtyChunks: replayedChunks` = вернуть баг с потерей пикселей. Сделать единый `bootGame(db)` / `GameRuntime.fromLoaded(...)`.
- **Нет хука для рассылки.** Нужен `onCommit(events)` после успешного коммита, чтобы WS рассылал только закоммиченное.
- **`stop()` не запрещает новые команды.** Добавить флаг `stopping`: `run`/`addPlayer` после него — reject. Порядок shutdown: перестать принимать → `runtime.stop()` → закрыть сокеты → `close()` БД.
- **`addPlayer` не идемпотентен**: два параллельных логина = двойные стартовые строки ledger и сброс состояния. Возвращать существующего игрока.
- **`commit()`**: обернуть в `try` весь вызов, включая `takeBatch`.
- **`addPlayer` до коммита строки `users`** = FK-ошибка = фатальный выход. Сначала коммит `users`, потом `addPlayer`.
- **Бан и гильдия** живут в `users`/памяти, не в рантайме: обработчики должны обновлять обе стороны.
- **`MIGRATIONS_DIR`** через `import.meta.dir` сломается при `bun build` — передавать путь явно или копировать `drizzle/`.
- `chunk_snapshots` не чистится — ок для 512×512, вернуться при большом холсте.

## Заметки для Плана 2c (из ревью Плана 2b)

- **Сессия проверяется только при upgrade.** Logout, истечение сессии и новый бан не трогают открытые сокеты. Нужна команда «выкинуть сокеты пользователя» (через топик `user:<id>`) и команда движка, обновляющая бан/гильдию **существующего** игрока: `addPlayer` для существующих ничего не меняет.
- **Discord-логин** должен на каждом входе вызывать `users.set(id, username)` (переименования) и обновлять `guildMember` у игрока.
- **tRPC-мутации** — только через `runtime.run` с `await`: тогда обновления игрока и лента рассылаются `handleCommit` автоматически. Проверять `Origin` у мутаций, как у WS (Lax-cookie уходит и с соседних поддоменов).
- **Маршрутизация:** tRPC-обработчик монтировать в `route()` до 404.
- **Сессии** не чистятся — периодический `DELETE ... WHERE expires_at < now()`.
- **Имена не уникальны** — в UI показывать аватар/id рядом с именем.

## Заметки для Плана 3 (клиент, из ревью Плана 2b)

- **`hello.bootId`**: при смене — сбросить все чанки и их версии.
- **Правило дельт**: `toVersion ≤ local` → отбросить; `fromVersion == local` → применить; `fromVersion > local` → перезагрузить; во время HTTP-загрузки чанка буферизовать дельты. `subscribed` подтверждает только новые чанки; версия из подтверждения > загруженной → перезагрузить.
- **Сообщения до `hello`** не придут (исправлено), но `player`/дельта могут прийти раньше собственного `placed`.
- **Rate limit** общий для SUBSCRIBE и PLACE (40 burst, 20/с, превышение → 1008): дебаунсить SUBSCRIBE при панорамировании.
- **Коды закрытия:** 1012 — рестарт сервера (переподключиться с backoff), 1008 — флуд, 1003 — битый кадр. Неотправленные PLACE не повторять автоматически.
- **Декодеры** принимают `Uint8Array`: при `binaryType = "arraybuffer"` оборачивать `new Uint8Array(data)`.
- **Dev-окружение:** Vite-прокси на `/ws`, `/chunk`, `/auth` (у `/chunk` нет CORS, cookie привязана к хосту; dev-логин редиректит на `/`).

## Заметки для Плана 3 (из ревью Плана 2c)

- **Vite-прокси** должен включать и `/trpc` (у сервера нет CORS). `Origin` браузера (`http://localhost:5173`) должен дойти до сервера без изменений: без `changeOrigin` и без переписывания `Origin`.
- **tRPC-клиент:** `httpBatchLink({ url: "/trpc" })`, без трансформера, `@trpc/client` строго `11.19.0`. Игровые исходы — `{ ok: false, code }` в данных; исключения только 401 / 429 (общий лимит пользователя, не ретраить) / 400 (сообщение zod не показывать пользователю).
- **`import type { AppRouter }`** тянет типы сервера (drizzle, Bun). Нужны раздельные tsconfig (project references) для `apps/web` (DOM) и `apps/server` (`types: ["bun"]`), либо вынести тип роутера в отдельную точку входа.
- **`me`** может вернуть `player: null` для вошедшего пользователя без игрока; членство в гильдии и возраст аккаунта `me` не сообщает (если UI должен показывать «вы зритель» заранее — расширить `me`).
- **Production** обязан выставлять `NODE_ENV=production` (иначе tRPC отдаёт stack trace) — проверить в Плане 6. — закрыто в 6

## Заметки для Плана 3b (из финального ревью Плана 3a)

- **Backoff без jitter**: все клиенты после рестарта сервера переподключаются одновременно (0.5/1.5/3.5/7.5/15.5/25.5 с). Добавить jitter; рассмотреть быстрый первый retry на код 1012 и меньший потолок.
- **`cameraToSearch` → `replaceState` теряет прочие query-параметры и hash** (например `?login_error=`). При обработке ошибок входа сначала прочитать и убрать параметр, потом включать синхронизацию URL (или сливать параметры).
- **`dropChunk` и лимит 64 чанков** не проверены вживую (при холсте 512² все 4 чанка всегда видны) — проверить на холсте ≥ 4096².
- **Смена DPR без смены размера** (перетаскивание окна между мониторами) не замечается — `matchMedia("(resolution: …)")`.
- **Трекпад:** двухпальцевый скролл сейчас зумит, `deltaX` игнорируется.
- **Незавершённые загрузки чанков** не отменяются при уходе чанка из вида (только при dispose) — лишний трафик при быстром панорамировании больших холстов.
- **`@rave/shared` тянет zod в бандл** (нормально, если 3b использует tRPC/zod на клиенте; иначе — sub-export `protocol`).
- **iOS:** `-webkit-user-select: none` / `-webkit-touch-callout: none` на хосте холста; `onCellTap` уже проброшен через `CanvasView`.
- Бандл 575 КБ (173 КБ gzip, в основном Pixi) — code splitting по желанию.

## Заметки для Плана 3c (из финального ревью Плана 3b)

- **Важно — расхождение часов:** `planPlacement`/`chargesAt`/`isFrozen` сравнивают `Date.now()` клиента с серверными метками. Отстающие часы блокируют отправку («Нет зарядов»/«Вы заморожены»). Добавить `serverNow` в `hello` и `player`, хранить смещение и использовать его в HUD, баннере заморозки и предпроверке.
- **Монотонные часы для таймаута ожидания** (`performance.now()`): шаг системных часов назад может оставить ожидающий пиксель навсегда.
- **Поздний `placed` после тоста «Нет ответа»** игнорируется — для взрыва игрок не увидит объяснения. Держать небольшой набор истёкших `reqId`.
- **Дедупликация тостов** (повторные клики без зарядов) и постоянно смонтированные live-регионы для `role="status"`.
- `title` у статов HUD недостижим (`pointer-events: none`); свотчи 32 px (< 44 px), нет Home/End в радиогруппе.
- Фиксированный отступ 128 px для баннера на телефоне ломается при большом `chargeCap` — раскладка через flex.
- Выключать режим бомбы при `inventory.bomb = 0`; клик мышью при открытом выборе касанием должен сбрасывать выбор.
- Бандл 590 КБ — code splitting вместе с миникартой/детектором.

## Заметки для Плана 5 (из финального ревью Плана 4b и открытые хвосты 3c/4a)

- **Админский бан** должен писать в БД и в движок (`engine.setAccess`) одновременно и отправлять игроку новый `player`; единый источник банов для всех досок и профилей (территория сейчас смотрит в движок, остальное — в БД); сбрасывать кеш рейтингов при бане. — закрыто в 5a
- **Сезоны:** ключи кеша рейтингов (30 с) и пиксельного кеша профилей (5 мин) не содержат `season` — при смене сезона очищать или добавить сезон в ключ.
- **IP за прокси:** лимитеры по IP берут `server.requestIP` — за Caddy все клиенты будут одним IP (поллинг рейтингов ~600 зрителей упрётся в 20/с). Доверенный `X-Forwarded-For` (План 6). — закрыто в 6
- **`/overview`** без лимита по IP. — закрыто в 6
- **Доступ:** `effectiveAccess` знает одну причину; при бане + «не в гильдии» после истечения бана клиент покажет «ok», сервер откажет. Можно отдавать все причины. — закрыто в 5a
- **Тепловая карта** включает пиксели, поставленные вместе с бомбой (по спеке 2.9); блоки 8×8 + число активных бомб чуть сужают поиск чужих бомб — решение сохранено осознанно.
- **Нет тестов:** «профиль не содержит лишних ключей» (раздел 9.5 спеки), обрезка топ-50 и `me` вне топа, тепловая карта на неквадратном/растущем холсте; компонентные тесты (`SidePanel` фокус/Esc, видимость меню, сброс запросов при смене пользователя, `ChunkBoundary`, маршрутизация ленты). — закрыто в 5a (серверная часть: ключи профиля, топ-50/`me`, тепловая карта на выросшем холсте; компонентные тесты остаются открытыми)
- На десктопе открытая панель закрывает кнопку «Выйти»; имена в ленте фиксируются на момент события (важно для переименований/банов). — закрыто в 5a
- ErrorBoundary с заблокированным чанком вручную не проверен.
- `config:defaults` перезапишет правки админа, когда появится редактор конфига — убрать или защитить. — закрыто в 5a
- Не делать: показ своих бомб на миникарте — по спеке бомбы невидимы даже автору.

## Заметки для Плана 6 (из финального ревью Плана 5b)

- Цепочки откатов: откат игрока не трогает клетки, где последнее событие — `mod_rollback`, восстановивший его пиксель (откат B, затем T); при рейдах — «Откатить к моменту». Возможное решение — хранить в `pixel_events` ссылку на восстановленное событие.
- Откат игрока по всему холсту без лимита: тяжёлый превью-запрос и один синхронный шаг движка; ввести лимит или применять частями. — закрыто в 6 (лимит 200 000 клеток, `too_many_cells`)
- `areaOwners` — топ-20 авторов: мелкого грифера в людной области не выбрать (только откат по всему холсту из `/admin`); тай-брейк и лимит не покрыты тестами.
- Гонки доступа: `ensurePlayer` применяет доступ вне per-user очереди (окно в миллисекунды), второй одновременный первый вход не ждёт перечитывания, проверка `unban` вне очереди (двойная запись в журнале). — закрыто в 6
- Hub зависит от `db` ради `ensurePlayer` — можно передать колбэк. — закрыто в 6
- UI модерации: превью области внизу вкладки, далеко от нажатой кнопки; ссылки на игроков стандартного синего цвета и уводят со страницы игры; на телефоне кнопки инструментов админа сжимают палитру; «1 клеток»; инспектор без «Повторить»; ▭ мышью не даёт панорамировать — подсказка или модификатор. — закрыто в 6
- Тесты: протягивание области в `session.ts`, компонентные тесты вкладки «Модерация».
- Dev-БД: перед проверкой 5b сделан дамп (`pg_dump -Fc`), проверка затронула только тестовые клетки (≈900,600).
