# Rave Battle — дизайн v1

Дата: 2026-10-07
Статус: согласован, ожидает финального ревью спеки

## 1. Концепция

Мультиплеерная браузерная игра для одного Discord-сервера: общий pixel battle-холст, в который встроена механика сапёра.

Главная идея: **бомба — это защита своего арта**. Игрок может заминировать свой пиксель; любой, кто попытается перекрасить заминированную клетку, подрывается — пиксель не ставится, жертва получает штраф, автор бомбы — бонус. Бомбы невидимы для всех (включая автора). Информацию о бомбах можно получить только расходными инструментами сапёра: детектор показывает цифру (сколько бомб в 3×3), дефьюзер снимает бомбу.

Целевая аудитория — один Discord-сервер, но архитектура должна держать тысячи онлайна на одном инстансе (принцип 80/20).

## 2. Игровые правила

Все числа ниже — стартовые значения **динамического конфига** (раздел 6), меняются админом на лету. Изменение конфига действует только на будущие события; купленные предметы и активные бомбы не пересчитываются.

### 2.1 Ресурсы игрока

| Ресурс | Старт | Пополнение |
|---|---|---|
| Заряды пикселей | 10, максимум 10 | +1 каждые 30 с; во время заморозки не восстанавливаются |
| Монеты | 100 | +1 за поставленный пиксель, бонусы, дейлик |
| Бомбы | 3 | магазин, дейлик |
| Детектор | 5 использований | магазин (+5 использований за покупку), дейлик |
| Дефьюзер | 0 | магазин (+2 использования за покупку), дейлик |

Заряды считаются лениво: хранится `{charges, charges_updated_at, frozen_until}`, текущее значение вычисляется при обращении.

### 2.2 Действия

| Действие | Стоимость | Результат |
|---|---|---|
| Поставить пиксель | 1 заряд | Клетка красится в выбранный цвет, игрок становится владельцем клетки, +1 монета |
| Поставить пиксель с бомбой | 1 заряд + 1 бомба | То же + на клетке скрытая бомба. Запрещено, если у игрока уже 20 активных бомб. Бомбу нельзя повесить на клетку без её перекраски |
| Детектор | 1 использование | Игрок получает число бомб в квадрате 3×3 вокруг выбранной клетки (включая её). Видит только он. Заряд пикселей не тратится |
| Дефьюзер | 1 использование | Если на клетке бомба — снимается; за чужую +20 монет и +1 в «сапёры», за свою — 0 и без статистики. Если бомбы нет — использование сгорает. Заряд пикселей не тратится |

Клиент хранит результаты детектора в localStorage вместе со временем замера и показывает возраст («12 мин назад»), со временем визуально приглушая цифру. Сервер не уведомляет об устаревании замера (это само по себе утечка информации). Синхронизации между устройствами нет.

### 2.3 Взрыв

Происходит при попытке поставить пиксель (с бомбой или без) на клетку с активной бомбой:

- пиксель **не ставится**, заряд потрачен, бомба удаляется, клетка остаётся как была;
- если жертва ставила пиксель с бомбой, её бомба **не расходуется** (остаётся в инвентаре);
- жертва: заморозка 60 с (действия и восстановление зарядов заблокированы), −10 монет (баланс не уходит ниже 0);
- автор бомбы: +15 монет, +1 в рейтинг бомберов (с учётом анти-фарма);
- **подрыв на собственной бомбе**: заморозка 120 с, −20 монет, бонуса нет, в рейтинг бомберов не идёт, засчитывается в `self_explosions`;
- жертва видит анимацию взрыва; в ленту событий уходит «💥 X подорвался на бомбе Y» **без координат**; остальные игроки на холсте ничего не видят.

### 2.4 Анти-фарм

- Цена бомбы (30) > бонуса автору (15) — подрываться «по дружбе» экономически невыгодно.
- В рейтинг бомберов одна пара «автор → жертва» засчитывается не более 3 раз за сутки (монетный бонус при этом начисляется).
- Самообезвреживание и самоподрыв не дают ни монет, ни очков рейтинга.

### 2.5 Магазин

Только внутриигровые монеты, никаких реальных платежей.

| Товар | Цена |
|---|---|
| Бомба | 30 |
| Детектор (+5 использований) | 40 |
| Дефьюзер (+2 использования) | 150 |
| Буст ёмкости зарядов (+5 к максимуму, до конца сезона) | задаётся в конфиге |
| Открываемые цвета | задаются в конфиге (у каждого цвета палитры с `unlock: "shop"` своя цена) |

Ориентир баланса: активный игрок ≈ 120 пикселей/час ≈ 120 монет/час.

### 2.6 Дейлик

Календарь из 7 дней по кругу. Пропуск дня не сбрасывает прогресс — игрок просто забирает следующую награду при следующем заходе (не более одной награды в календарные сутки). Смена суток в 00:00 часового пояса из конфига (по умолчанию `Europe/Moscow`).

| День | Награда |
|---|---|
| 1 | 30 монет |
| 2 | 1 бомба |
| 3 | Детектор (+5) |
| 4 | 50 монет |
| 5 | 2 бомбы |
| 6 | Детектор (+5) |
| 7 | Дефьюзер (+2) |

### 2.7 Доступ

- Вход только через Discord OAuth2. Без входа холст можно смотреть.
- Опциональная проверка членства в Discord-сервере: если задан `DISCORD_GUILD_ID`, игроки не из гильдии могут только смотреть.
- Минимальный возраст Discord-аккаунта (вычисляется из snowflake ID): по умолчанию 30 дней, в конфиге. Младшие аккаунты — только просмотр, с сообщением, когда смогут играть.
- Забаненные игроки — только просмотр.

### 2.8 Холст и палитра

- Размер по умолчанию 512×512, хранится в динамическом конфиге, может **только увеличиваться** (валидация запрещает уменьшение).
- Холст разбит на чанки 256×256 (размер чанка — константа в коде).
- Пиксель = 1 байт = индекс в палитре (0–255).
- Палитра — типизированные записи в конфиге:

```
{
  id: 0..255,
  type: "solid" | "animated" | "gradient",   // расширяемо
  base: "#RRGGBB",                            // фолбэк-цвет для рендера
  params: object,                             // параметры эффекта
  unlock: "default" | "shop" | "daily" | "achievement",
  price?: number                              // для unlock = "shop"
}
```

- 0–31 — базовые цвета (`unlock: "default"`), 32–255 — слоты под открываемые и эффектные цвета.
- В v1 клиент рендерит **все** записи цветом `base`; рендер эффектов (`animated`, `gradient`) — вне скоупа v1, но бэк, БД и протокол уже их поддерживают.
- Визуальный стиль: неон, тёмная тема.

### 2.9 Статистика и рейтинги

Лидерборды за день / неделю / всё время:

1. **Художники** — поставленные пиксели.
2. **Бомберы** — подрывы чужих игроков на твоих бомбах (с анти-фармом).
3. **Сапёры** — обезвреженные чужие бомбы.
4. **Камикадзе** — подрывы на чужих бомбах.
5. **Территория** — сколько пикселей на холсте сейчас принадлежит игроку (только «всё время / сейчас»).

Профиль игрока: все счётчики выше, самоподрывы, число активных бомб (без координат), любимый цвет, дата регистрации, тепловая карта **поставленных пикселей** (не бомб).

Живая лента событий (взрывы, обезвреживания) — без координат.

## 3. Архитектура

### 3.1 Стек

- Рантайм и пакетный менеджер: **Bun**, bun workspaces.
- Бэкенд: `Bun.serve` (HTTP + нативные WebSocket), tRPC (fetch adapter), Drizzle ORM, PostgreSQL, zod.
- Фронтенд: Vite, React, tRPC client, **PixiJS** (v8) для холста.
- Деплой: VPS + Docker Compose (postgres, server, caddy).

### 3.2 Структура репозитория

```
rave-battle/
├── apps/
│   ├── server/          Bun: HTTP (tRPC + auth + chunk endpoint) + WS + GameEngine
│   └── web/             Vite + React + PixiJS
├── packages/
│   └── shared/          zod-схема конфига, бинарный протокол WS, типы, константы
├── docker-compose.yml
└── Caddyfile
```

### 3.3 Сервер

```
                 ┌────────────────────── Bun.serve ──────────────────────┐
  HTTP /trpc ───►│ tRPC: auth · shop · stats · profile · daily · admin   │
  /auth/*    ───►│ Discord OAuth callback                                │
  /chunk/*   ───►│ начальная загрузка чанков                             │
                 │        │                                              │
                 │        ▼  все изменения игрового состояния — только    │
  WS /ws ───────►│ ┌──────────────── GameEngine ───────────────┐         │
  (binary)       │ │ CanvasStore   чанки: colors Uint8Array,   │         │
                 │ │               owners Int32Array           │         │
                 │ │ BombStore     Map<cell, bomb>             │         │
                 │ │ PlayerState   заряды, монеты, инвентарь   │         │
                 │ │ ConfigStore   динамический конфиг         │         │
                 │ └───────────────────┬───────────────────────┘         │
                 │                     ▼                                 │
                 │ Persister: group commit ~100 мс ──► Postgres          │
                 │ Broadcaster: pub/sub по топикам чанков ──► клиенты    │
                 └───────────────────────────────────────────────────────┘
```

Принципы:

1. **GameEngine — единственный писатель игрового состояния.** Пиксели, покупки, дейлик, детектор, дефьюзер, действия админа — всё проходит через него. Однопоточность JS исключает гонки (например, одновременная трата последней бомбы на покупку и установку).
2. **GameEngine без I/O.** Принимает команду и текущее время, возвращает результат и список событий для персиста/рассылки. Это делает его детерминированно тестируемым.
3. **Group commit.** События копятся ~100 мс и пишутся одной транзакцией. Подтверждение (`ACK`) игроку и рассылка (`CHUNK_DELTA`, лента) происходят **только после коммита**. Клиент рисует пиксель оптимистично и откатывает при `REJECT`.
4. **Fail-fast при ошибке БД.** Если коммит не удался, ни одно действие батча не подтверждается и не рассылается, процесс завершается, Docker перезапускает его, состояние восстанавливается из БД.
5. **Восстановление при старте.** Последние `chunk_snapshots` → проигрывание `pixel_events` после `last_event_id` → загрузка активных бомб, конфига, счётчиков анти-фарма за сегодня. Снапшоты чанков пишутся каждые 5 минут.
6. **Realtime по подписке.** Клиент подписывается на видимые чанки; Bun pub/sub рассылает дельты только подписчикам. Дельты батчатся: один бинарный фрейм на чанк за тик ~50 мс.
7. **Масштабирование.** Один инстанс. `CanvasStore` и `Broadcaster` за интерфейсами, чтобы при необходимости вынести состояние в Redis без переписывания движка (в v1 не делаем).

### 3.4 Поток «поставить пиксель»

```
client ──[PLACE x,y,color,withBomb]──► WS
  GameEngine:
    бан / возраст / гильдия / заморозка / заряды / цвет открыт /
    (withBomb: бомба в инвентаре, лимит активных бомб)
      └─ нарушение ──► [REJECT code]
    на клетке активная бомба?
      да  → взрыв: штрафы, бонус автору (анти-фарм), удалить бомбу
      нет → записать цвет и владельца (+ бомбу), +1 монета, обновить территорию
  Persister commit
      ──► [ACK + состояние игрока] автору действия  (или [EXPLODED] жертве)
      ──► [CHUNK_DELTA] подписчикам чанка (только если пиксель поставлен)
      ──► [FEED] всем (только при взрыве, без координат)
```

### 3.5 Протоколы

- **WS (бинарный, версионированный)** — горячий путь: `PLACE`, `SUBSCRIBE/UNSUBSCRIBE` чанков, `ACK`, `REJECT`, `CHUNK_DELTA`, `PLAYER_STATE`, `EXPLODED`, `FEED`, `CONFIG_CHANGED`, `ONLINE_COUNT`.
- **tRPC** — магазин, рейтинги, профиль, дейлик, детектор, дефьюзер, админка. Вызовы, меняющие игровое состояние, внутри идут через GameEngine.
- **HTTP `GET /chunk/:cx/:cy`** — сжатый бинарь цветов чанка + версия чанка. Далее клиент догоняет дельтами; при разрыве версий — перезагрузка чанка.

### 3.6 Авторизация

- Discord OAuth2 authorization code с параметром `state`. Скоупы: `identify`; дополнительно `guilds`, если задан `DISCORD_GUILD_ID`.
- Сессия в таблице `sessions`, в браузер — cookie `httpOnly`, `Secure`, `SameSite=Lax`.
- WebSocket аутентифицируется той же cookie при upgrade (один домен за Caddy).
- Админы — список Discord ID в env `ADMIN_DISCORD_IDS`; проверка на сервере в каждой `admin.*` процедуре.
- Dev-only вход без Discord для локальной разработки и e2e, отключён в production.

### 3.7 Клиент

- PixiJS используется императивно внутри одного React-компонента холста; React отвечает за UI вокруг (магазин, рейтинги, профиль, лента, админка).
- Каждый чанк — текстура из RGBA-буфера (конвертация индексов палитры), `scaleMode: nearest`. Входящие дельты пишутся в CPU-буфер, текстура обновляется раз в кадр.
- Зум к курсору/точке щипка от «весь холст» до ~64×; сетка видна только на большом зуме; overlay с цифрами детектора; миникарта; координаты и зум в URL (`?x=&y=&z=`).
- Мобильная поддержка: pinch-зум, drag-пан, режим «тап выбирает клетку → кнопка подтверждает», адаптивные панели.
- Обработка потери WebGL-контекста — пересоздание текстур из CPU-буферов.
- Рендерер холста за интерфейсом.

## 4. Модель данных

`users.id` — `serial` (int32), потому что владельцы пикселей хранятся в памяти и снапшотах как `Int32Array`.

### Пользователи и доступ

- `users`: `id serial`, `discord_id` unique, `username`, `avatar`, `discord_created_at`, `banned_until`, `ban_reason`, `created_at`, `last_seen_at`.
- `sessions`: `id` (хэш токена), `user_id`, `expires_at`, `created_at`.
- `seasons`: `id`, `name`, `started_at`, `ended_at`. В v1 одна бессрочная запись.

### Состояние игрока (ключ `user_id + season_id`)

- `player_state`: `coins`, `charges`, `charges_updated_at`, `frozen_until`, `charge_cap_bonus`, `daily_step`, `daily_last_claim` (date).
- `inventory`: `item` (`bomb` | `detector` | `defuser`), `amount` (для детектора/дефьюзера — число использований).
- `unlocked_colors` (без сезона): `user_id`, `color_id`, `source`, `created_at`.
- `ledger`: `id`, `user_id`, `season_id`, `item` (`coins` | `bomb` | `detector` | `defuser` | `color`), `delta`, `balance_after`, `reason` (`shop` | `daily` | `explosion` | `bomb_bonus` | `defuse` | `use` | `admin` | `start`), `ref jsonb`, `created_at`. Монета за пиксель в ledger построчно не пишется — агрегируется в `stats_daily.coins_from_pixels`.

### Холст

- `chunk_snapshots`: `season_id`, `cx`, `cy`, `colors bytea` (65 536 байт), `owners bytea` (int32 × 65 536), `last_event_id`, `created_at`.
- `pixel_events`: `id bigserial`, `season_id`, `x`, `y`, `user_id`, `color_id`, `prev_color_id`, `prev_user_id`, `kind` (`place` | `mod_rollback` | `mod_clear`), `created_at`. Индексы: `(season_id, user_id, created_at)`, `(season_id, x, y, id)`.
- `bombs`: `id`, `season_id`, `x`, `y`, `owner_id`, `created_at`, `removed_at`, `removed_reason` (`exploded` | `defused` | `moderated`), `removed_by`. Частичный уникальный индекс `(season_id, x, y) WHERE removed_at IS NULL`. Таблица — также история подрывов/обезвреживаний.

### Статистика

- `stats_daily`: `user_id`, `season_id`, `date`, `pixels`, `bombs_triggered`, `explosions_suffered`, `self_explosions`, `defused`, `coins_from_pixels`.
- Рейтинги день/неделя/всё время — `SUM` по диапазону дат; топы кэшируются в памяти и пересчитываются раз в ~30 с.
- «Территория» — инкрементальный счётчик в памяти по массиву владельцев.

### Админка

- `game_config`: `version serial`, `data jsonb`, `created_by`, `comment`, `created_at`. Актуальная — максимальная версия. Откат = вставка копии старой версии.
- `mod_log`: `id`, `admin_id`, `action`, `target_user_id`, `params jsonb`, `created_at`.

Оценка объёма: пиковая верхняя граница ~100 пикселей/с ≈ 8,6 млн строк `pixel_events` в сутки. Партиционирование по месяцам — при необходимости, вне v1.

## 5. Админка и модерация

Страница `/admin`, доступна только пользователям из `ADMIN_DISCORD_IDS`.

| Инструмент | Описание |
|---|---|
| Редактор конфига | Форма по секциям, zod-валидация с ошибками по полям, история версий, откат |
| Бан | Временный / постоянный, с причиной |
| Откат игрока | Отмена пикселей игрока за период, по всему холсту или в области; восстановление предыдущего состояния клеток |
| Очистка области | Залить прямоугольник цветом фона или откатить к моменту времени |
| Снять бомбы | Все бомбы игрока или все бомбы в области |
| Правка игрока | Монеты и инвентарь, с записью в `ledger` (`reason = admin`) |
| Инспектор клетки | Автор, история клетки, наличие бомбы |
| Журнал модерации | Все действия админов |

Все действия модерации проходят через GameEngine и пишутся в `mod_log`.

## 6. Динамический конфиг

- Хранится в `game_config` (jsonb, версии), кэшируется в памяти, при изменении рассылается клиентам через `CONFIG_CHANGED`.
- Схема — zod в `packages/shared`, общая для сервера, клиента и формы админки.
- Содержит: размер холста, палитру, параметры зарядов, штрафы и бонусы, длительности заморозок, лимит активных бомб, анти-фарм лимит пары, использования детектора/дефьюзера за покупку, цены магазина, стартовый инвентарь, награды дейлика, часовой пояс суток, монеты за пиксель, минимальный возраст Discord-аккаунта.
- Env (статично): Discord OAuth credentials, `DATABASE_URL`, `DISCORD_GUILD_ID` (опционально), `ADMIN_DISCORD_IDS`, публичный URL, секрет сессий.
- Валидация запрещает: уменьшение размера холста, удаление/смену типа записей палитры, которые уже использованы на холсте.

## 7. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нарушение правил | `REJECT` с кодом причины; клиент откатывает оптимистичный пиксель и показывает тост |
| Обрыв WS | Переподключение с экспоненциальным backoff, переподписка на видимые чанки, перезагрузка чанков при разрыве версий |
| Ошибка коммита в БД | Fail-fast (раздел 3.3, п. 4) |
| Невалидный конфиг | Отклоняется до записи, ошибки по полям |
| Потеря WebGL-контекста | Пересоздание текстур из CPU-буферов |

## 8. Безопасность

- Данные о бомбах никогда не покидают сервер (кроме: цифра детектора владельцу, результат дефьюзера, факт взрыва жертве, админский инспектор). Отдельный тест проверяет, что сериализация чанков и ответов не содержит бомб.
- Отсутствие утечек через отказы: бомба на заминированную клетку → взрыв, а не «тут уже бомба».
- Валидация всех входящих данных: zod для tRPC, проверки границ/длины для бинарного WS.
- Rate limit на WS-сообщения и tRPC (по пользователю и IP); злоупотребление → разрыв соединения.
- Секреты только в env; в репозитории — `.env.example`.

## 9. Тестирование (`bun test`)

1. **GameEngine** — основной объём: заряды и заморозка, взрыв (чужая/своя бомба), лимит бомб, анти-фарм, детектор (3×3, края холста), дефьюзер, покупки, дейлик (цикл, пропуски, смена суток в часовом поясе), открытые цвета, экономика.
2. **Persister и восстановление** — интеграция с реальным Postgres в Docker: запись → «падение» → старт → состояние совпадает.
3. **Протокол** — round-trip кодирования/декодирования бинарных сообщений.
4. **Откат модератором** — сценарии с наложением пикселей нескольких игроков.
5. **Отсутствие утечки бомб** — сериализаторы чанков, ленты, профиля, ошибок.
6. **E2E (Playwright)** — dev-вход, поставить пиксель, увидеть его во второй вкладке.

## 10. Скоуп

**Входит в v1:** разделы 2–9 целиком, мобильная поддержка, Docker Compose деплой.

**Не входит в v1 (заложено в архитектуре):**

- рендер эффектных пикселей (animated / gradient);
- UI сезонов и их смена (в данных уже есть `season_id`);
- Redis и горизонтальное масштабирование;
- IP-флаги мультиаккаунтов;
- партиционирование `pixel_events`;
- донат и любые реальные платежи (решено не делать).
