| # | Изменение | Затрагивает |

## 2. Рассмотрено и отклонено

Пункты, которые обсуждались, но остаются как в v1:

- **Работа без БД в памяти.** Остаётся fail-fast (v1, 3.3 п. 4): ни одно действие не подтверждается без коммита, процесс завершается, Docker его перезапускает. Это проще и не может потерять подтверждённые действия.
- **Анимация чужих взрывов для всех.** Взрыв по-прежнему видит только жертва, в ленте он без координат (v1, 2.3). Показ места взрыва другим игрокам раскрывает, где стоит чужая защита.
- **Удаление `pixel_events` старше 30 дней.** Журнал хранится вечно: на нём держатся откат «к моменту», откат игрока, инспектор клетки и тепловая карта профиля. Партиционирование по месяцам остаётся вне скоупа, как в v1.
- **`idempotencyKey` для покупок.** tRPC-мутации клиент автоматически не повторяет (`httpBatchLink`, без retry у мутаций), поэтому двойного списания из-за повтора нет. Вернуться к ключу, если появятся автоповторы.
- **Проверка членства в Discord-сервере** не включается: `DISCORD_GUILD_ID` не задаётся. Механизм из v1 остаётся в коде.
- **Внешние копии бэкапов** не нужны, бэкапы остаются локальными на VPS.

## 3. i18n

### 3.1 Принципы

- Сервер не отправляет клиенту готовых текстов для пользователя. Он отправляет коды и параметры: коды отказа WS (`REJECT`), игровые исходы tRPC (`{ ok: false, code }`), события ленты, причины недоступа, ошибки валидации конфига.
- Переводит клиент. Языки: `ru` (эталон) и `en`.
- Исключения, которые не переводятся: причина бана и комментарий к версии конфига. Это свободный текст админа, он показывается как есть.

### 3.2 Сервер

- Ошибки валидации конфига (`engine/config-change.ts` и zod-схема) переходят с русских строк на `{ path, code, params }`, например `{ path: "canvas.width", code: "canvas_shrink", params: { current: 512 } }`. Ошибкам zod присваивается код `invalid` с `zod`-кодом в параметрах.
- Проверка в тесте: в ответах сервера, кроме перечисленных исключений, нет кириллицы.

### 3.3 Клиент

- Библиотека: `i18next` + `react-i18next`.
- Словари — TS-модули в `apps/web/src/i18n/`: `ru.ts` эталонный, `en.ts` типизирован как `typeof ru`. Отсутствующий ключ ломает typecheck.
- Ключи сгруппированы по экранам (`hud.*`, `shop.*`, `admin.*`, `reject.*`, `feed.*`, …).
- Тест перебирает все коды отказа, исходов, ленты и валидации конфига из `@rave/shared` и проверяет, что у каждого есть перевод.
- Числа, даты и «12 мин назад» — через `Intl` с текущей локалью.
- Форма админки и сам холст текстов почти не содержат, но админка переводится полностью вместе со всем остальным.

### 3.4 Выбор языка

1. Явный выбор игрока: переключатель в профиле (для гостей — в меню).
2. Иначе `locale` из Discord (берётся при входе).
3. Иначе `navigator.language`.
4. Иначе `ru`.

Выбор вошедшего игрока хранится в новом поле `users.locale text NULL` (`ru` | `en`) и меняется tRPC-мутацией `settings.setLocale`. У гостя выбор лежит в `localStorage`. При входе из `localStorage` в профиль ничего не переносится: приоритет у сохранённого в профиле.

## 4. Эффектные цвета

### 4.1 Параметры в схеме

Сейчас `params` — свободный `record`. В v1.1 схема записи палитры становится дискриминированным union по `type`:

| `type` | `params` | Как выглядит |
|---|---|---|
| `solid` | `{}` | Цвет `base` |
| `animated` | `{ frames: hex[2..8], periodMs: 400..10000 }` | Пиксель по кругу меняет цвета `frames` за `periodMs`, с плавным переходом между кадрами |
| `gradient` | `{ stops: hex[2..6], scale: 4..256, angle: 0..359, speed: 0..1 }` | Цвет зависит от мировых координат клетки: вдоль направления `angle` с периодом `scale` клеток. Соседние клетки одного цвета вместе дают переливающуюся полосу; `speed > 0` медленно сдвигает градиент со временем |

- `base` остаётся фолбэком для миникарты, тепловой карты, превью в магазине на слабых устройствах и старых клиентов.
- Валидатор изменения конфига (v1, 6) уже запрещает менять тип цвета, который есть на холсте. `params` такого цвета менять можно.
- Миграция существующих данных не нужна: все текущие записи — `solid` с `{}`.

### 4.2 Рендер

Сейчас чанк хранится как RGBA-буфер, в который индексы палитры переводятся на CPU. В v1.1:

- Текстура чанка — `r8unorm`: один байт индекса палитры на клетку, прямо из массива `colors` без конвертации. Памяти на GPU в 4 раза меньше, обновление клетки — запись одного байта.
- Палитра — текстура данных 256 × N (строка 0 — `base`, строки 1..8 — кадры или стопы) плюс небольшой uniform-буфер с типом и параметрами каждой записи.
- Фрагментный шейдер (PixiJS v8 `Filter`/`Shader` для спрайта чанка) по индексу выбирает цвет: `solid` → `base`, `animated` → смешивание двух кадров по `time`, `gradient` → позиция клетки в мире (`chunkOrigin + uv · CHUNK_SIZE`) → цвет из стопов.
- Сэмплинг индексной текстуры — `nearest`, цвет вычисляется по центру клетки, поэтому границы пикселей остаются чёткими на любом зуме.
- `time` обновляется каждый кадр, только если на видимых чанках есть хотя бы один эффектный цвет (счётчик эффектных клеток ведётся по чанку). Иначе холст не перерисовывается без надобности.
- Настройка «Уменьшить движение» (и `prefers-reduced-motion`) замораживает `time`: эффекты рисуются статично.
- Потеря WebGL-контекста: индексные текстуры восстанавливаются из `colors`, палитра — из конфига.
- Если шейдеры недоступны или рендер упал при инициализации, клиент откатывается на текущий путь с RGBA-буфером и цветом `base`.

### 4.3 Магазин и админка

- В магазине и палитре свотчи эффектных цветов анимируются (CSS или маленький canvas), с подписью типа эффекта.
- В редакторе конфига у записи палитры — поля по типу (кадры, период, стопы, масштаб, угол, скорость) и живое превью на образце 16×16.
- Стартовые эффектные цвета в `config:defaults`: 4 `animated` и 4 `gradient` в слотах 40–47, `unlock: "shop"`. Цены выше обычных платных цветов.

## 5. Biome и CI

- Biome для lint и format по всему репозиторию, один `biome.json` в корне.
- Первый прогон форматирования — отдельным коммитом без других изменений.
- Скрипты `lint` (`biome check .`) и `format` (`biome format --write .`).
- Правила, которые массово ругаются на текущий код, сначала выключаются точечно с комментарием в `biome.json`, а не исправляются вперемешку с фичами.
- CI сейчас нет. Добавляется workflow GitHub Actions на каждый push и PR: `lint` → `typecheck` → `bun test` с сервисом Postgres 17 (база `rave_test`) → `build:web` → e2e (`bun run e2e`).

## 6. Нагрузочный тест

- Скрипт `scripts/load.ts`: N ботов (по умолчанию 1000) через dev-вход, каждый подписывается на чанки и ставит пиксели с максимальной разрешённой скоростью. Часть ботов ставит бомбы, часть использует детектор.
- Запуск вручную против локального прод-подобного стека (как e2e). В CI не входит.
- Отчёт: p50/p95/p99 от `PLACE` до `ACK`, от коммита до получения дельты другими ботами, длительность коммита, размер батча, память процесса.
- Цели: p99 `PLACE → ACK` < 150 мс, доставка дельты < 250 мс, коммит < 50 мс при 1000 ботов.

## 7. Метрики

- `GET /metrics` в текстовом формате Prometheus, без внешних зависимостей: онлайн (сокеты, игроки), действия в секунду по типам, отказы по кодам, длительность и размер коммита, длительность тика рассылки, rate-limit разрывы, память.
- Наружу через Caddy эндпоинт не публикуется (закрыт в `Caddyfile`), доступен только из Docker-сети. Сбор и дашборды — вне скоупа.

## 8. Ревизия интерфейса

Отдельный этап после этой спеки: аудит текущего клиентского и админского интерфейса и новый дизайн обоих. Результат — своя спека.

Порядок работ: сначала дизайн ревизии интерфейса, потом реализация клиентских частей v1.1 (i18n, эффектные цвета в UI) вместе с новым интерфейсом. И i18n, и редизайн трогают каждый компонент; если делать их порознь, строки придётся переносить дважды. Серверные части v1.1 (коды ошибок конфига, `users.locale`, схема палитры, метрики) и Biome от редизайна не зависят и могут идти сразу.

## 9. Тестирование

- i18n: полнота словарей (typecheck + тест по кодам), отсутствие кириллицы в ответах сервера, приоритет выбора языка.
- Палитра: схема `params` по типам, валидатор конфига, детерминированная функция «индекс + координата + время → цвет» в `@rave/shared`, общая для шейдера (как эталон в тестах) и для свотчей.
- Рендер: при `r8unorm` дельта меняет ровно один байт; фолбэк на RGBA при ошибке инициализации.
- Метрики: формат вывода, эндпоинт недоступен через Caddy (e2e).

## 10. Скоуп

**Входит в v1.1:** разделы 3–7, спека ревизии интерфейса (раздел 8).

**Не входит:** всё из раздела 2; языки кроме `ru` и `en`; эффекты кроме `animated` и `gradient`; сбор метрик и алерты.
